Captured against the full Compose stack (`docker compose up --build`: gunicorn,
config.settings.production, PostgreSQL 17), seeded with
`docker compose exec api python manage.py seed_demo_data`. Every block below is
the literal output of the command shown above it; only `created_at` is masked.

Production settings require an authenticated user, so a superuser was created
with `docker compose exec api python manage.py createsuperuser`, and the
commands authenticate with HTTP Basic auth:

    API=http://localhost:18960          # API_HOST_PORT was set to 18960 for this run
    DEMO_AUTH='demo@example.com:<password>'
    pick() { python3 -c 'import json,sys;d=json.load(sys.stdin);print(json.dumps({k:d[k] for k in sys.argv[1:]},indent=2))' "$@"; }

Metadata that does not match the registered schema is rejected before it
reaches the database (note the misspelled key):
$ curl -s -w '\nHTTP %{http_code}\n' -u "$DEMO_AUTH" -X POST "$API/inventory/" -H 'Content-Type: application/json' -d '{"name":"Typo","type":1,"language":37,"metadata":{"year":2010,"actors":["X"],"imdb_rating":8.8,"rotten_toamtoes_rating":87}}'
{"metadata":[{"type":"missing","loc":["rotten_tomatoes_rating"],"msg":"Field required"},{"type":"extra_forbidden","loc":["rotten_toamtoes_rating"],"msg":"Extra inputs are not permitted"}]}
HTTP 400

Filters reject malformed ids with a 400 rather than a server error:
$ curl -s -w '\nHTTP %{http_code}\n' -u "$DEMO_AUTH" "$API/inventory/?type=abc"
{"type":"Expected a positive integer id, got 'abc'."}
HTTP 400
